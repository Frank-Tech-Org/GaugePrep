# API specification

> Guidance only: the API contract is the OpenAPI document generated from the code, and the code wins where they differ.

The endpoint catalogue of release 1. Conventions are those of architecture Section 11; this document lists what exists, who may call it, and the rules each endpoint enforces. The OpenAPI schema generated by Django Ninja is the contract; this document is what engineers implement against and what reviewers check the OpenAPI against.

## 1. Conventions in brief

- Base path `/api/v1`. JSON. Session cookie authentication; CSRF token header `X-CSRFToken` on every write.
- Errors use problem details (RFC 9457) with a stable `code` (Section 12) and a `detail` in the learner's interface language.
- Writes that may be retried carry `Idempotency-Key` (a UUID). The server stores the key with the result for 24 hours and returns the same result on repeat.
- Lists use cursor pagination: `?cursor=...&limit=` (default 20, maximum 100); responses carry `next_cursor`.
- Times are ISO 8601 UTC. Timers use the server time returned in the `X-Server-Time` header of every response.
- Access column: **public** (no session), **learner** (signed in), **verified** (signed in with a verified email), **premium** (active Premium entitlement), **reviewer**, **support**, **owner**, **service** (internal API token).
- "Usage" means the endpoint checks and increments a usage counter in `billing` (PRD PAY-7) before doing any paid work; a refused request returns `usage_limit_reached` with the counter values and the reset time.

## 12. Error codes

| Code | HTTP | Meaning |
|---|---|---|
| `validation_error` | 422 | Field errors listed in `errors` |
| `not_authenticated` | 401 | No valid session |
| `forbidden` | 403 | Role or ownership check failed |
| `not_verified` | 403 | Email verification needed |
| `premium_required` | 402 | Needs an active Premium entitlement |
| `usage_limit_reached` | 429 | Daily or monthly usage limit; body has `metric`, `used`, `limit`, `resets_at` |
| `rate_limited` | 429 | Too many requests; `Retry-After` header |
| `age_below_minimum` | 422 | Date of birth under 16 |
| `code_invalid`, `code_expired`, `code_attempts_exceeded` | 422 | Verification code problems |
| `paper_closed` | 409 | The paper's deadline has passed or it was submitted |
| `already_played` | 409 | A simulation recording was already played |
| `form_exhausted` | 409 | Never returned to the learner: the oldest form is reused and marked as a repeat (spec 7.4); kept for internal use |
| `idempotency_conflict` | 409 | Same key used with a different body |
| `payment_failed` | 402 | Provider declined; `provider_message` included |
| `refund_not_eligible` | 422 | Outside the refund rule |
| `content_unavailable` | 404 | Version retired or not published |
| `grading_unavailable` | 503 | Grader paused (for example during a provider outage); the production is kept and graded later |

## 13. Internal API (voice examiner)

Path `/internal/v1`, private network only, `Authorization: Bearer <service token>` (architecture 3.3, 11).

| Method and path | Purpose |
|---|---|
| GET `/speaking-sessions/{room}` | Session context: learner ID, interface language, tasks in order with timings, EO1 questions, EO2 card and examiner facts, EO3 question and follow-ups, learner's current level estimate, mode (practice or simulation) |
| POST `/speaking-sessions/{room}/events` | Append events: task started and ended, preparation started and ended, examiner turns, interruptions, recitation probes, errors |
| POST `/speaking-sessions/{room}/recordings` | Register an uploaded recording (R2 key, task, duration) |
| POST `/speaking-sessions/{room}/transcripts` | Live transcript segments with timing and confidence |
| POST `/speaking-sessions/{room}/end` | Close the session; triggers batch transcription and grading per task; settles usage |

## 14. Console (internal)

The internal console uses Django views and the Django admin, not this API. It covers PRD CMS-1 to CMS-8 and ADM-1 to ADM-4: content import review, batch approval and publication, audio listening queue, form builder, flag queue, learner lookup without essay content, manual entitlement and refund actions, result report verification, plans and prices, operations dashboard, audit log. Every console action writes `admin.audit_log`.
